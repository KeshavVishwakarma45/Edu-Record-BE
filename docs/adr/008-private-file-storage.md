# ADR-008: Private file storage behind an authenticated route

- Status: Accepted
- Date: 2026-11-01

## Context

Photos, signatures and scans are personal data. NFR-03 asks for signed links later (P3).

## Decision

- All file handling goes through `src/utils/storage.js` (`save`, `getStream`, `remove`).
  P1 writes to a private `UPLOAD_DIR` that is never served as static files.
- A `File` record keeps tenant, institute, type and size. Files are read only through
  `GET /api/v1/files/:id`, which runs the full middleware chain; another institute's file is 404.
- Storage keys are generated by the server (UUID), never taken from the user's file name.
- `middleware/upload.js`: images (jpg, png, webp) up to 2 MB, PDFs up to 5 MB, and the first bytes
  of the file must match the declared type.
- API responses carry `Cache-Control: no-store`.

## Consequences

- Good: P3 can switch to cloud storage with signed links without changing module code.
- Bad: an `<img src>` cannot send the token, so the client fetches files as blobs.
